# 台灣機器人社群．共治章程（Headless Committee）v1.0 草案

> **本章程的存在目的**：讓社群不綁在任何一個人身上、不被任何廠商把持，並且辦活動不卡關。
> 設計衝突時，以此順序裁決：
> **① 防把持 ＞ ② 可交接 ＞ ③ 低摩擦。**
>
> 章程分兩層：
> - **第一層《憲章》**——價值、委員資格與少數鐵則，**最難修改**（防把持的保險絲在這層）。
> - **第二層《運作細則》**——流程、金額、操作，**可較快修改**。
>
> 正本維護於公開 GitHub（修訂＝Pull Request，可追溯）；Notion 為工作空間並定期匯出備份。

---

## 第一層　憲章（Constitution）

### §1　宗旨

本社群由一群機器人相關產業的人，在業餘時間的聚會裡逐漸長成。我們想要的，是一個能凝聚**跨組織**（公司、學校、獨立開發者）專業人士的平台——讓機器人相關人員可以一起交流資訊、技術與產業洞察，甚至靠社群的力量找到專業領域的講師，透過工作坊釐清並深入特定技術的進階操作。

**本社群的活動以機器人及其相關領域為範圍**，包含但不限於：機器人軟硬體、ROS 生態系、感測與視覺、控制、運動規劃、機構設計、機器學習與 robot learning、模擬與部署，以及相關產業應用。與機器人無關之主題不在本社群舉辦範圍內。

社群最有價值，卻最難量化的，是這幾件事交織在一起：透過彼此的連結做**人才媒合**，讓需要人的組織與想學的人對接，降低雙方的試錯成本；在信任建立後的**分組討論**裡，交換那些有深度 insight 的看法和經驗；並以**讀書會與工作坊**共同學習，讓出社會後仍有一群人一起精進，最終回饋到整個產業。

主要交流形式上，推薦以**小組討論（建議 ≤ 8 人）**為核心，重交流甚於講座。

若成員或廠商曾因社群而獲得幫助，我們也鼓勵以各種方式回饋社群——無論是分享經驗、協助辦活動、指導後進，或提供資源——讓社群得以永續經營。

### §2　技術優先於金錢

利益媒合是社群的功能之一，我們不迴避；但**在技術交流的場合，我們不談錢、不被商業綁架**。贊助讓活動辦得起來，但不能改變「這裡是開放交流的地方」這件事。任何提案（包括贊助）若傷害此核心，即屬違憲。

### §3　中立性原則（防把持核心）

1. 社群**不背書任何產品或公司**；贊助商露出一律標示為「贊助」，不得包裝成「社群推薦」。
2. **金錢不換取決策權**：明文禁止「花錢買決策影響力（pay-to-play）」。**贊助不換取委員席次、不換取任何治理權。**
3. **金流與議程分離**：掌管錢的人與決定議程的人，不得是同一人。
4. **資產中立持有**：社群名稱、商標、網域等由財務代管單位中性持有，不歸任何個人或公司。
5. **個資保護**：報名等個人資料僅用於社群通知與活動聯繫；除非參與者明確同意（opt-in），不提供予贊助商或第三方；委員會與財務代管單位對持有之個資負保密義務，並依《個人資料保護法》回應查詢、更正或刪除之請求。

### §4　開放原則

1. 活動的**正式產出**（公開議程的投影片、錄影）盡量以創用 CC 授權公開；講者得事前聲明例外。**分組討論與私下交流不在此列**，尊重營業秘密與個人意願。
2. **財務季報對全體社群公開**（不只給贊助商）。
3. **決議公開可查**，留存於僅新增不刪除的紀錄（GitHub）。

### §5　無主委原則

1. 不設固定領導人／主委。
2. 任何委員經表決通過，皆可代表社群舉辦活動。
3. **無主委 ≠ 無召集人**：每場活動都有一位「認領到的召集人」對基本運作負責；營運工作輪流認領，不長期集中於一人。

### §6　委員資格

> 委員一律以**個人身分**參與。**本社群不設法人委員**——公司、學校、機構皆不具委員身分與表決權，僅能以贊助或協力方式支持社群（見 §D）。這是刻意的簡化：法人席次會帶來代表性、迴避、名額比例等大量複雜度與漏洞，與社群規模不相稱。

**取得委員資格（簡易程序）**
- 申請人**參加過 ≥ 2 次社群活動**，填寫入會報名表。
- **私訊 2 位現役委員**取得同意，並將其姓名填入表單。
- 由引薦委員於委員會頻道**公告周知**，無人於 **48 小時**內提出具理由反對即生效。
- 每位委員**申報任職公司**，供利益衝突判斷。
- 委員**以個人身分參與**，不代表所屬公司；提名、表決與對外發言時應以「個人」而非「公司代表」自居（brand-free）。
- 委員**無固定任期**。

**委員人數與招募**

| 現役委員人數 | 招募政策 |
|---|---|
| **> 12 人** | **不主動公開招募**；仍可循簡易程序個別引薦加入 |
| **< 8 人** | **公開募集委員** |
| **< 5 人** | **進入落日條款倒數**（見 §G） |

- **同一公司任職者 ≤ 2 席**——固定值，不隨委員總數放寬。這條是讓「修改憲章個人專屬」真正安全的關鍵，不可省。

**喪失委員資格**

- **未出席委員季度會議連續 3 次** → **自動退出委員名冊**。非除名、不影響聲譽，日後想回來循簡易程序即可。
	- 前提：該期間確有召開季度會議。社群整體停擺而未召開者，該次不計入。
- **除名**（違反下列情事之一，即觸發除名程序）：
	1. 違反《相處底線》（附錄 A）；
	2. **擅自挪用社群金錢**，或未經核可之支出、隱匿收支；
	3. 利益衝突應迴避而未迴避。
	- 程序：**具理由之提案 + 現役委員過半同意**，**當事人迴避**。
	- **任何單一召集人不得逕自批准或開除委員。**

**利益迴避**
- 活動或提案若涉及**特定公司或法人之利益**（該公司贊助、提供場地、參與招募、產品露出等），**與該公司有僱傭、持股或其他利害關係之委員應迴避表決**，並於紀錄中標註。

### §7　修改章程

- **《憲章》（第一層）**：需**現役委員過半同意**，且事前**公告 14 天**供社群公評。**來自同一雇主之委員，其同意票合計不得構成通過所需票數的多數。**
- **《運作細則》（第二層）**：適用【重大事項】規則（見 §B）。
- 章程、委員資格、除名等規則之修改，一律屬本層事項。

### §8　相處底線之最高性

《相處底線（附錄 A）》是不可違反的底線，位階高於一切運作便利。

## 第二層　運作細則（Bylaws）

### A　委員的主要任務

委員會**不設專門職務**（不設主委、財務長等固定頭銜），改以**任務領域**劃分，由委員視情況認領：

1. **金錢**——收支核銷、與財務代管單位對接、季度公開財報。
2. **章程管理**——章程維護、決議紀錄、名冊更新。
3. **大型活動**——年會等大型活動之審查與籌辦。
4. **網站與社群維運**——Discord、GitHub Pages、Notion、網域、帳號安全。

- 每場活動另設**可認領的臨時角色**：召集、場地、紀錄、財務對接。不需要每個都有人，**核心是至少有人認領「召集」**。
- **金流與議程分離**（§3.3）：經手金錢者不同時主導該案議程。

### B　決策機制

> 危險的決策預設「不通過」，日常的決策預設「通過」。

**日常事務｜一般活動（do-ocracy + 惰性共識，預設通過）**
1. 提案人於 `#提案` 貼出：主題、日期、地點、預算來源。
2. **72 小時公示**；期間無「具理由的反對」且累積 **≥ 3 個贊成**，即**視為通過**（沉默＝同意）。
3. **出現具理由的反對 → 啟動大型活動會議程序**（見下），由該會議決定是否進行。
4. **接棒制度**：**連續兩場小聚不得由同一人擔任召集人**，讓辦活動的能力與經驗分散。**但書**：若距上一場活動已**超過 3 個月無人發起**，則不受此限，任何人皆可直接發起——寧可有人辦，也不要因為規則而沒有活動。

**大型活動｜加嚴審查（強制會議 + 過半，預設不通過）**

> **認定門檻**（符合任一即屬大型活動）：**動用社群資金或對外募集贊助**；或以社群名義**對外正式宣傳**（如年會等級）。
> 不以參與人數認定——小活動也可能人多，且一般活動多能以門票沖銷、不需請款。**判準是「動到錢」與「對外代表社群」。**

1. 提案人於 `#提案` 公告，**公告期至少 2 天**；公告後 **2 週內**召開審查會議（實體或線上皆可）。
2. 會議須有 **≥ 現役委員 1/3 出席（且不少於 5 人）**，且**同一組織之出席者合計不得超過 2 位**，避免單一組織主導審查。
3. 出席委員**過半同意**方可啟動。
4. **金流沿用 §D 規則**（送件≠核准、雙人核准、核銷制）。
5. 須有 **≥ 3 位社群成員（不限委員身分）共同籌辦**，避免大型活動仰賴單一人力。

**重大事項｜錢／贊助／運作細則／委員資格（法定人數 + 過半，預設不通過）**
1. **法定人數 = 現役委員的 1/2 參與投票**。
2. 若未達法定人數 → **數日後召開第二次表決，法定人數降為現役的 1/3**（反僵局）。
3. 通過需**參與投票者過半數同意**；利益相關者**迴避**。

**反對票規則**
- 空的反對**不計**；有效反對須**具名 + 附理由 +（盡量）提替代方案**。

**釐清機制（適用所有提案類型）**
- **第一層｜討論**：出現 **1 個**具理由的反對或質疑 → 於原提案討論串回應釐清。
- **第二層｜強制釐清**：反對或質疑者達 **現役委員的 1/4 以上** → 提案**自動暫停**，須召開會議釐清爭點後，方得繼續進行或重新表決。暫停期間不得逕行執行。

### C　委員季度會議

- 每季召開一次**委員會議**，**約 30 分鐘、線上**即可；**即使無議程亦照常召開**，上線聊聊也算。
- 目的有三：維持社群心跳、確認名冊現況、徵求下一季活動的召集人。
- **連續 3 次未出席者自動退出名冊**（見 §6）。
- 建議固定時段（例如每季第一個週三晚上），並提前於 Discord 公告。

### D　財務

**保管與角色**
- 金流由**財務代管單位科斯高（GOSCUP Inc.）**保管；社群**不自持大額現金**。（OCF 開放文化基金會之金流實務亦由科斯高代管，故兩者為同一套帳務窗口，**不能互為備援**。）應**書面確認終止條款與備援安排**（見 §G）。
- **代管單位對社群任何決策無表決權、無否決權**。
- 認領「金錢」任務之委員負責彙整核銷、對接代管單位、提季度公開財報。

**收支實務（依代管單位規定）**
- **行政管理費：每筆入帳收取**（費率依科斯高當年度規定，2026 年為 10%、已含營業稅）。
- **收入**：境內公司贊助**開立發票**（需提供統編、公司全稱、發票品名 ≤30 字、含稅總額）；境外公司開 invoice。
- **出款**：每月**第一、第三個週四**出款（遇假日順延），請**提前至少 7 個工作天**提出。
- **核銷單據**：每筆需填項目、金額、單據類型、說明、收款戶名／銀行帳號。單據以**發票**為主；無發票者用**收據**；兩者皆無則附**領據／經手人證明**。
- **公共意外責任險**：中華民國境內 **200 人以上**活動須投保。

**資金使用規則**

> 兩個原則：**① 專款專用**——社群資金只為 §1 宗旨而存在，**不屬於任何個人**。**② 報帳為主、不編年度預算**——以實支實付、憑單核銷為常態；只有大額支出才需要事先開會提領。

- **一般活動以門票自給自足**：餐食與場地原則上以門票收入 cover，**不需請款**。
- **活動一律收費**（即使金額不高）。收費除了打平成本，也是**過濾機制**——避免純粹來吃免費餐食、無意參與交流的人稀釋活動品質。
- **小聚盈餘處理**：若小聚收費後有盈餘，**由該場總召自由心證，捐予財務代管單位（科斯高）**，作為社群共同資源。總召應於活動後公開說明金額。
- 若門票收入不足以打平，差額得循核銷程序由社群資金補足。

**社群資金的主要用途**
1. **協助辦活動之成員的餐食與場地費用**。
2. 活動直接成本：投影／網路、耗材、保險。
3. 講者與協力者之交通、住宿等必要支出。
4. 設備租借、共用工具與線上服務訂閱（Notion、密碼保管庫、網域）。
5. **社群維運之 AI／生產力工具訂閱**（如 Gemini、Notion 等）：屬持續性支出，**須走【重大事項】核可**後訂閱，並公開項目與費用。
6. **微型補助**（讀書會、工作坊、開源產出等，見 §F）。
7. 代管單位之行政費用及必要之稅費。

**大型活動之標準給付**（金額為上限，得從低或不支給）

| 對象 | 標準 |
|---|---|
| 工作人員 | **每人每日 NT$500** |
| 講者 | **每場 talk NT$1,500** |

- 具**公務人員**或其他受法令／任職單位限制身分者，應**自行確認其身分可否受領**；若不便受領酬勞，**改以核銷實際交通費**辦理，或聲明放棄。
- **講者交通費**：NT$1,500 已含一般市內交通，**原則上不另支**；惟**跨縣市遠道**講者得檢據核實另支，**上限 NT$500**（實報實銷）。用意是補貼部分成本、不讓車馬費變成收入。由活動總召認定並公開。
- 一般活動不適用本表，回歸門票自給自足原則。

**交通費核銷憑證**（依《營利事業所得稅查核準則》第 74 條）

| 交通工具 | 所需憑證 |
|---|---|
| 捷運、公車、火車 | **經手人（本人）證明即可**，無須票根；建議附電子票證消費明細 |
| 計程車 | **經手人證明即可**；有收據更好 |
| Uber 等叫車平台 | Email 電子乘車證明，或 App **行程明細截圖** |
| 高鐵 | 票根或購票證明；**當日往返得以經手人證明代之** |
| 飛機 | 機票票根（或電子機票）＋登機證 |
| 自行開車 | 里程與路線說明；ETC 通行費得以經手人證明為憑 |

- 一律填具**支出證明單／領據**，載明**事由、日期、起訖地點、金額**。
- 原則：**能留憑證就留**，經手人證明是最後手段。

**不得動支之用途**
1. **任何形式的盈餘分配**予委員、成員或其關係人（非分配原則）。
2. 支付**特定公司之品牌曝光／行銷成本**。
3. 投資、放貸、代墊他人款項、或購置與社群宗旨無關之資產。
4. 政治獻金、宗教用途，或對特定商業產品之背書性支出。

**核銷與提領**
- **常態＝事後核銷**：先花、憑收據請款，由代管方撥付。
- **例外＝事先提領**：僅**大額預付款**（場地訂金、抽獎獎品、大量餐飲預訂）需**事先經委員會決議**；亦得**請代管單位直接代為匯款**予廠商，社群不經手現金（優先採用）。
- 大額之認定門檻由委員會議定並公開。
- **分權內控**：送件的人 ≠ 核准的人；對外付款採**雙人核准**；小額設單簽快速通道。
- **季度公開財報** + 代管方對帳 = 兩層帳。
- **結餘不得分配**，留供後續活動使用；社群結束時依 §G 處理。

**贊助**
- 公司、學校、機構皆可贊助，但**贊助不換取委員席次或任何治理權**（§3.2）。
- **一般活動贊助**與**大型活動贊助**均**無金額上限**，由該場總召與協力夥伴依實際需求決定並公開。
- **社群為主體、贊助商為附屬**：以社群名義舉辦的活動，**社群 logo 須在贊助商 logo 之前或之上**。
- **可以露出 logo**（甚至每場活動都可露出所有贊助商），也**可以有簡短的產品宣傳**；但宣傳**不得包裝成議程的一部分**、不得取得社群背書；若要在議程中**插入宣傳環節**，須經**活動總召與協力夥伴同意**。
- **公司自家的宣傳活動，不得以社群名義舉辦。**
- **不對單一贊助者形成依賴**：場地、設備、人力等非現金支援若長期集中於單一公司，委員會應主動尋求替代方案，確保保底活動在失去該支援時仍辦得起來。**贊助與資源提供者名單公開。**

**「宣傳」的定義（本章程通用）**

> 機器人領域裡，很多分享是「教開發者怎麼用某個工具」，這對社群有實質價值，**不應被當成宣傳而懲罰**。界線在**意圖**，不在有沒有提到公司或產品。

- **算「宣傳」**：內容帶有**明確希望聽眾去採購、採用、下單該公司產品／服務的意圖**——報價、促銷、限時優惠、「歡迎洽詢購買」、比較競品以促成銷售等。
- **不算宣傳（屬教學／分享）**：以**教學、經驗分享、釐清工具用法**為形式與目的者——即使內容大量使用某公司的工具、甚至通篇在講該公司的框架，只要**目的是幫聽眾把東西做出來、而非促成購買**，就不算宣傳。
- **有爭議時**：由該場活動的**總召與協力夥伴**共同認定，結果公開。**認定者若任職／持股於被認定的公司須迴避**；皆有利益衝突時提交委員會。

**參與者資料**
- 贊助商**不得**索取社群過往所有活動的參與者資料；**僅得索取自己贊助之該場活動**的資料，且限於已依 §3.5 明確同意（opt-in）提供聯絡方式的參與者。
- 索取時須**註明用途**，不得挪作原申明用途以外之使用。

### E　非委員辦活動（協力主辦）

- 非委員個人須**參加過 ≥ 2 次社群活動**（確保了解社群文化與活動方式），由**任一現役委員擔任引薦人聯署**，循【日常事務】規則提案。
- 引薦委員對該場的**相處底線遵循與流程**負責。
- **委員得協助非委員在社群 Luma 帳號上開設活動頁面**，讓活動能觸及既有社群成員。此為行政協助，不代表社群為該活動內容背書。
- 公司、學校、機構欲舉辦活動者，同樣循本機制，由委員引薦聯署；適用哪一軌依 §B 認定。

### F　紀錄、工具與個人開發者支持

**紀錄與工具**
- **治理正本住在公開 GitHub**：章程、決議、修訂以編號留存；修章程＝PR + 審核 + 合併（竄改可追溯）。
- **兩個 repo 分流**：
	- **公開 repo**：章程、決議紀錄、公開財報（去識別化）、活動成果。
	- **私有 repo**：報名個資、金流明細、帳號清單等機密資料——**務必設為 private**。
- **Notion 為工作空間**，定期匯出 Markdown 推到**私有** GitHub repo 作異地備份。
- 帳號原則：能多人帳號的服務用**各自帳號 + 角色權限、≥ 2 名不同公司 Owner**；只能單一帳號者用**共享密碼保管庫（含 2FA 種子）**，離開者於庫中撤權即可。
- 名冊住在 GitHub，狀態變更由**當事人或任一委員直接發 PR** 更新。

**個人開發者支持**
- **微型補助**：對讀書會、工作坊、開源產出（投影片、範例程式、教材）、講者交通等，得核發小額補助。補助**走【重大事項】規則**，受補助者**迴避**；受補助人與用途**公開**。補助不構成背書。
- **回饋管道**：曾因社群獲益的成員或公司，鼓勵以講題、場地、設備、實習名額、時間等方式回饋（§1）；金錢以外的回饋同等受重視。

### G　社群結束與金流處理（Sunset）

> 社群不是法人；錢不在社群手上，在代管單位。因此「結束」要處理的其實是三件事：**什麼時候算結束、剩下的錢往哪去、代管單位若先倒了怎麼辦**。這些必須**在沒事的時候先寫好**。

**觸發條件**（符合任一，任一現役委員得啟動結束程序）
- **現役委員少於 5 人**，且經公開募集 **3 個月**內未能補足至 5 人以上；或
- 連續 **12 個月**未舉辦任何活動；或
- 委員會主動提案結束。

**程序**
1. 提案結束後**公告至少 30 天**，供全體社群成員（含非委員）表達意見或提出接手方案。
2. 若公告期內有 **≥ 3 位**成員願意組成新的委員會接手，優先走「重啟」而非「結束」。
3. 無人接手，或委員會仍決議結束者，經現役委員【重大事項】規則通過後生效；產出**結案財報**並公開。

**剩餘資金處理**（**不得歸屬任何個人或營利法人**）
1. 先清償已發生之費用與代管單位之應付款項。
2. 剩餘款項依【重大事項】決議，**捐贈予宗旨相近之非營利或學術單位**，優先順序建議：機器人相關系所／實驗室之**學生獎助**或學生社團活動經費 → 台灣其他開源／機器人開發者社群 → 財務代管單位本身之公益用途。
3. 由**代管單位依其規範執行撥付**，社群不經手現金。
4. **不宜自行持有實體設備**（無法律主體可登記所有權、無人負保管與保險責任）。若希望留下設備，應以**捐贈給學研單位／學生社團**辦理，並得約定「對本社群成員開放使用」。

**代管單位先行結束時的備援**
- 應**指定備援代管單位**。⚠️ **OCF 的金流亦由科斯高代管，兩者不能互為備援**；須另擇獨立於科斯高、宗旨相近的台灣非營利組織。
- 收到終止通知後 **90 天內**完成資金移轉至備援單位。
- 簽約時應**書面確認終止條款**（通知期、資金移轉方式、資料交還）。

**數位資產處置**
- **先刪除個資與機密**（私有 repo、Notion、密碼保管庫、表單後台），並通知代管單位一併銷毀其保管之個資。
- 去識別化後的治理紀錄、章程、公開財報、活動成果 → 轉唯讀公開存檔；GitHub repo 加註「已結束／archived」。
- 社群名稱、商標、網域**不得移轉予任何公司**；若無合適承接的非營利單位，寧可停用。
